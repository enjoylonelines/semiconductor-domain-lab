# CI/CD and E2E gate(종단 간 관문) verification

Date: 2026-09-27
Scope: CI/CD(지속적 통합/지속적 배포) verification; no deployment target exists.

## Gate design

- `contract`: portable unit(단위), regression(회귀), contract(계약), and
  environment-independent fault-injection(장애 주입) tests on every push and
  pull request.
- `postgres-integration`: a disposable PostgreSQL 16 service validates the
  API(응용 프로그램 인터페이스) → durable Run(지속 작업) → distinct worker
  path in GitHub-hosted CI. Recorded OpenSTA tests remain explicitly skipped
  there because the fixture is absent.
- `opensta-postgres-e2e`: a manual self-hosted `eda-opensta` gate starts a
  disposable PostgreSQL container on a dynamic loopback port, then runs the
  complete suite. It covers the recorded actual OpenSTA fixture and B1–B3
  worker-loss fault injection.

The project has no deployable production environment. Therefore this is a
release-readiness gate, not evidence of a deployment, rollback, or production
CD operation.

## Local mirror result

The self-hosted workflow's dynamic-port pattern was reproduced locally with a
new disposable PostgreSQL 16 container at `127.0.0.1:32768`:

```text
EDA_POSTGRES_TEST_DSN=postgresql://…@127.0.0.1:32768/eda_e2e \
PYTHONPATH=src uv run python -W error::ResourceWarning \
  -m unittest discover -s tests -q

Ran 66 tests in 5.344s
OK
```

The container was removed after the run. This verifies the workflow's local
execution assumptions. GitHub-hosted CI and the self-hosted workflow dispatch
are separate remote observations and are recorded only after they complete.
