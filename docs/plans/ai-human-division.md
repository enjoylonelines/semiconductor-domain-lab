# AI와 학습자의 역할 분담

이 작업의 목적은 문서를 많이 만드는 것이 아니라, 지원자가 반도체/IP/EDA 흐름을 자기 말로 설명할 수 있게 하는 것이다. 따라서 AI는 조사·구현·실험 자동화·정리 비용을 줄이고, 학습자는 specification·사전 예측·결과 해석·최종 판단·설명을 소유한다. 현재 Deep Dive의 역할 표와 다섯 Human Gate는 [범위 정본 §0.1](research-and-scope-2026-09-23.md#01-human-owned--ai-delegation--2026-09-24)을 따른다. 아래 광범위한 도메인 학습/5분 설명은 보조 활동이며, 현재 parser→service Deep Dive의 Product/Engineering STOP을 대체하지 않는다.

## AI가 맡는 일

| 영역 | AI의 책임 | 제한 |
|---|---|---|
| 자료 조사 | 현재·과거 JD, 회사 제품, 표준·벤더 자료를 찾고 출처를 정리 | 출처 없는 사실을 만들지 않음 |
| 구조화 | JD를 서버/API, 비동기 실행, 데이터, 파일 처리, 운영, HW 협업으로 분류 | 회사 내부 구조로 단정하지 않음 |
| 초안 작성 | Domain Map, EDA 흐름, 용어표, 면접 답변 초안 작성 | 최종 이해를 대신하지 않음 |
| 실험 지원 | fixture/test/harness·반복 실행·집계 및 사람이 정한 specification 구현 | Human Prediction 뒤 실행; 실제 EDA 결과나 실리콘 검증으로 포장하지 않음 |
| 검토 | 문서 링크, 사실/추론 구분, 누락·모순 점검 | 합격·경험을 대신 판정하지 않음 |
| 범위 관리 | 새 주제를 백로그로 보내고 Stop Rule을 상기 | 학습 시간을 무한히 늘리지 않음 |

## 내가 직접 해야 하는 일

| 영역 | 직접 확인할 결과 |
|---|---|
| 도메인 이해 | MCU→SoC→IP→Controller/PHY→PCIe·UCIe·MIPI·SerDes 관계를 백지에 그림 |
| EDA 이해 | 디지털과 아날로그 흐름의 차이, simulation·verification·synthesis·P&R·sign-off를 말로 설명 |
| 용어 습득 | 핵심 용어 20개를 보지 않고 뜻과 업무 예문을 설명 |
| 판단 | 작업 완료, 파싱 성공, 설계 검사 통과를 서로 다른 상태로 판단 |
| 실험 | synthetic parser를 직접 실행하고 정상·누락·단위 오류·중복 입력 결과를 확인 |
| 면접 준비 | 5분 설명을 실제로 말하고, 모르는 부분과 과장된 표현을 제거 |
| 경험 경계 | 실제로 해본 임베디드·SW 경험과 이번 학습에서 새로 이해한 내용을 분리 |

## 실행 순서

1. AI가 JD와 회사 자료를 분류한다. 나는 각 분류가 실제 지원 업무와 어떻게 연결되는지 설명한다.
2. AI가 Domain Map과 EDA 흐름 초안을 만든다. 나는 자료를 닫고 직접 다시 그린다.
3. AI가 용어표와 parser 초안을 만든다. 나는 핵심 용어를 설명하고 parser 결과를 판정한다.
4. AI가 면접 답변을 검토한다. 나는 5분 동안 직접 말하고, 근거 없는 표현을 삭제한다.

## 보조 학습 확인과 현재 완료 기준

다음 네 가지는 도메인 입문 확인이다. 용어 수나 5분 설명을 프로젝트 성과·현재 Deep Dive 완료로 세지 않는다. Engineering STOP에는 범위 정본의 실제 fixture·측정과 **AI/README/메모 없이 약 15분 설명, 핵심 코드의 작은 변경·결과 예측·debugging 방향 설명**이 추가로 필요하다. 사용자 숙지 증거는 아직 unrecorded다.

- MCU → SoC → IP → PHY/SerDes → EDA → SW backend를 5분 안에 설명한다.
- EDA 실행 완료와 설계 검증 통과의 차이를 설명한다.
- synthetic parser의 입력 오류와 출력 상태를 판단한다.
- 퀄리타스 JD의 API·queue·RDB·파싱·자동화 업무가 왜 필요한지 설명한다.

AI가 만든 문장을 읽을 수 있는 것은 시작 조건이고, 문서를 닫은 뒤 틀린 설명을 고칠 수 있는 것이 완료 조건이다.
